# TK 标题检查 · C 方案本地版

基于 C 方案的个人标题检查工具。单条检测、候选手工修改与复检、CSV/XLSX 批量导入、CSV 结果导出、人工草稿复核和本机历史。界面使用真实计算结果，不使用设计稿中的模拟统计。

## 运行

需要 Node.js 22.12+ 或24+。

```bash
npm ci
npm run dev
```

打开终端显示的本机地址。`npm run build` 生成 `dist/`，`npm run preview` 在本机预览构建产物。当前未部署公网。

本机可双击 `启动标题检查.command`；或执行 `PATH=/opt/homebrew/bin:$PATH npm run dev`。本机默认 npm 包装器指向失效路径，且打包的 Node 无法加载第三方原生模块；启动脚本只为当前进程选择已有 Homebrew Node，不修改全局配置。

## 使用

1. 在单条检测输入标题，选择范围。可先“填入示例”体验；示例事实不是已核验的商品资料。
2. 检测后查看命中片段、原因、来源和规则覆盖。只有“整理空格”会按明确动作整理候选，营销词及商品属性需手工处理。
3. 修改候选并重新检测。补充商品事实来源、确认资料完整，再逐项核对事实和限制后可记录人工复核；该记录仍为草稿，不代表正式采用或店铺发布。
4. 批量导入请先下载模板。支持 UTF-8 CSV 和仅一张工作表的 XLSX，每批100条、5MB。保留物理源行号，错误行显示失败；不自动套用缺失的市场。
5. 检查历史保存在当前浏览器和地址的 localStorage。换浏览器、清除站点数据或改变端口不会带走历史。请使用导出保留结果；超过500条或存储失败会提示，不静默丢弃旧记录。

6. 在“规则与词库”添加个人规则，填写条件和修改提示，可先试测再保存。支持包含任一词句、所有词句都未出现、字符数少于或多于；词句是忽略大小写的字面子串，长度按 Unicode 码点计算。规则仅存本机，是个人检查条件，不是平台政策。
7. 规则变更后请重新检测原标题及修改稿，才能记录新的人工复核。历史保留当时的命中和版本；CSV 保留这些快照。规则数据损坏时检测暂停，可在规则页先下载备份，再确认重置；跨标签冲突时保留草稿并重新载入。没有 Web Locks 的浏览器只能尽力比较保存前数据，无法保证同时写入的完全互斥。

## 导入字段

| 列名 | 说明 |
| --- | --- |
| title_original | 商品原标题，必需 |
| market | US / unknown；未填则 unknown |
| language | en / unknown |
| category | fitness / other / unknown |
| brand_status | branded / unbranded / unknown |
| brand_name | 规范品牌名 |
| product_type | 对照匹配用的英文产品类型；同义表达仍需人工核验 |
| features | 商品事实，每行一项；CSV 多行须正确引号包裹 |
| facts_source | 资料编号或来源说明，不自动请求此链接 |
| facts_complete | true / false；表示录入者声明，不代表系统鉴真 |

标题及文本字段用文本单元格，不接店铺/商品ID关联。XLSX 公式、宏、外部关系和多工作表拒绝导入，请先转换为纯值。导出 CSV 对可能被电子表格执行的单元格加单引号保护；界面和历史中的原文不改动。

## 已知边界

当前是 v0.2 个人本地版本，研究规则基于2026-10-28官方来源复核，不是全市场生产规则包。所有有效结果保留“待人工核验（草稿）”；无论是否命中，不承诺平台审核通过。T09自动关键词堆砌未启用，T11事实语义仍需人工核验。80/150/200/255不作为发布硬限制。

未接入真实AI、服务器账号和团队权限、跨设备同步、规则在线发布、批次断点恢复或店铺发布。该版本是现有完整PRD的可用子集，不代表P0/P1全量验收完成。
