# 手动自定义规则 PRD · v0.2

日期：2026-11-03。当前为评审修订后的实施版；在现有本地 React 标题检查器上增量实施。代码由 GPT-6.1 Terra 实施，Codex 最终审核，AGY CLI Claude Opus 5.5 已完成文字方案评审。

## 用户结果与范围

用户在“规则与词库”里新增自己的规则，不用改代码；保存后用于单条检测、修改稿复检及批量检测。内置 T01–T11 保留，不被个人规则覆盖。新增规则固定标为“自定义规则（非平台政策）”，既不能让平台研究规则失效，也不能把没有命中宣称为平台审核通过。

本次交付新增、编辑、启用/停用、删除、保存前试测与浏览器本地持久化。不接 AI 判断、店铺、服务器、跨设备同步、任意代码或正则表达式、规则导入导出与复杂 AND/OR 组合。多智能体指开发分工，不是产品新增模型服务。

## 规则表单与匹配契约

必填规则名称（最多60码点）、条件类型、条件值、命中后的修改提示（最多500码点）。严重程度：待核验/建议，默认建议。适用范围：市场任意/US；语言任意/en；类目任意/fitness/other。未知输入仅匹配任意范围；受限范围遇 unknown 跳过并解释。

四类条件：包含任一词句时提示、所有词句都未出现时提示（出现任意一个就不提示）、字符数少于、字符数多于。关键词每行一个，最多20个，每项最多100码点，去除首尾空白和空行，重复词句提示修正，不能为空；匹配为 NFC 规范化后的字面子串，不区分大小写，bike 也匹配 e-bike/bikes，不做整词或语义判断。标点按字面处理，绝不当正则。长度按原文 Unicode 码点含空格计算，整数0–5000，严格小于/大于，等于不命中。

自定义规则最多100条，使用 C- 前缀稳定随机 ID，不与内置冲突；新规则默认启用，可在保存前调整；编辑保留 ID 并增加修订号。空格、重复条件、无效数字、超限时具体提示，不保存无效规则。完整 schema 由同一校验函数覆盖 UI、存储及引擎边界。

表单提供可选测试标题与相同市场/语言/类目选择，显示未命中/命中/范围不符；尚未保存或停用的草稿可单独试测匹配逻辑，清楚标注“只试测当前草稿，不保存”。改条件或测试上下文后旧试测失效。示例只填表单，不自动保存。

## 生效与历史

规则保存在独立 localStorage key，带 schemaVersion 和规则集合版本。保存成功才更新当前生效集合；空间不足/权限限制时保留编辑内容并显示未保存，不能显示已生效。损坏数据不静默覆盖，提示阻塞规则编辑和检测，保留原始数据供恢复。跨标签页通过 storage 事件同步；提交时检测原值是否改变，冲突不覆盖新值，提示重新载入后编辑。

每次检测以规则集合快照执行，只存集合版本、命中项快照（名称、提示、来源、修订号）和覆盖结果，不在每条历史复制完整规则定义。删除或编辑规则不改写历史。无效标题时所有规则跳过。批量开始时固定一次规则集合快照，避免同批版本混用。

规则变化后，已显示结果保留但标记“规则已更新，重新检测后才能记录复核”；清空当前未保存的复核勾选，旧历史复核记录作为历史保留。原文检测与候选复检必须使用同一当前版本后才能新增人工复核；重新检测原文时保留用户修改稿，避免丢稿。历史恢复也检查版本；旧版本历史可读，不会因新增字段而丢失。批量旧结果与导出显示各自实际版本，重新检测使用当前版本。CSV 补充自定义规则版本、命中来源与候选实际版本，保留已有列和公式防护。

## 界面与完成标准

沿用现有黑白灰界面与原生控件；内置、自定义分区，入口“添加自定义规则”，空态含可填入示例。单列移动表单，持久 label、字段错误、键盘焦点、主要触控目标至少44px；320/390px无横向溢出。规则列表解释条件、范围、状态，并能编辑、切换和删除；删除需用户在界面确认具体规则，历史快照不删。结果中展示用户所写修改提示与“自定义”来源，不伪造官方链接。

验收：新增包含规则→试测→保存→单条命中→候选修正复检→批量命中→导出版本→刷新保留；停用后不执行，编辑/删除不改历史；范围/字面标点/NFC/emoji/大小写/空输入/长度边界明确；存储损坏/配额/冲突不丢旧数据；规则变更无法绕过复核门槛。既有自动测试、构建及针对以上行为新增测试通过，浏览器验证核心路径和窄屏。

## Claude 5.5 评审后的最终契约

以下决定优先于初稿。评审模型 claude-opus-5-5-high，SUCCESS/1轮，基于文字而非代码。Codex采纳存储、版本、复核、恢复、Unicode与导出建议。现有历史校验本就接受C- ID与字符串来源；500条上限不裁剪旧记录。浏览器配额因环境变化，不承诺固定5MB或最大500条一定可保存。

1. 历史仅保存集合版本、命中和覆盖快照。配额失败保留原有数据，当前结果仍可导出。测试100条最大规则与500条记录逻辑和配额失败，不保证最大文本同时存得下。
2. 自定义待核验用 REVIEW，同样阻止人工复核；建议用 SUGGESTION。表单说明区别，摘要区分内置和自定义命中数。允许用户停用不适用规则，但必须重检，不能改变历史复核结论。
3. 内置 ruleVersion 不变；自定义集合每次保存、切换、删除和重置生成不可复用随机版本，或采用 setId+revision。旧历史缺少该字段时可读，但应用层视为过期。inspect(data)默认空集兼容旧调用。复核必须同时比较原文、候选和当前的内置及自定义版本。
4. 损坏数据保持阻塞检测，新增“下载损坏数据备份”及确认后“重置为空”。备份失败不重置，重置前核对原值未变，仅重置规则key，不触碰历史。这是异常恢复，不是常规规则导入导出。
5. 关键词 trim 后 NFC 规范化，使用 toLowerCase 不使用地区转换；上限按NFC后码点计数。高亮映射回原文码点，包含大小写扩展如İ。长度沿用原文码点，家庭emoji可有多个码点。子串例子使用 bike 匹配 bikes/e-bike，不声称匹配 bicycle。
6. CSV保留原14列，在尾部追加自定义规则集版本、命中来源、候选实际版本等明确列；所有文本仍使用公式防护。导出使用历史快照，不用当前规则名称覆盖。
7. other仅代表输入明确选择的其他类目；unknown不属于other，不自动转换无效beauty等值。覆盖说明包含范围跳过、停用、输入无效原因。
8. 跨标签改变不能悄悄更新旧表单的保存基线。冲突保留草稿并提供明确重新加载。Web Locks可用时串行提交，否则原值比较并如实记录限制，不引入同步服务。

当前为v0.2实施版，本地为开发快照；Notion现有实施页v0.2增量为权威当前稿。实际验证见同目录《测试与安全检查报告》的v0.2增量。

## 最终实施约定

集合版本字段为 customRuleVersion，每次修改生成 V-UUID，初次未保存的空集合为 empty-v1。原有 ruleVersion 保持内置规则含义。CSV原14列之后追加“自定义规则集版本、命中来源、候选内置规则版本、候选自定义规则集版本”。

旧结果过期后先重新检测原标题，保留同一原标题的修改稿并生成新结果记录，再复检修改稿；过期时直接复检候选被阻止，避免覆盖原来的历史复核。跨标签冲突保留草稿；编辑中的规则被另一页删除时可另存为新规则。

异常恢复的备份状态绑定当时原始数据；备份之后数据再次变化，必须重新下载备份才能重置。下载动作只能说明已触发，确认框要求用户确认文件已保存。仅重置自定义规则，不删除历史。

## 2026-11-04 内置规则目录开关

内置 T01–T08、T10–T11 的定义只读，可通过卡片右侧开关在本机启停。T09 尚未实现自动检查，开关不可用。停用 T11 不取消商品事实或人工复核的独立要求。自定义规则列表和编辑区开关位于右侧；已保存规则即时生效，新规则开关随表单保存。
